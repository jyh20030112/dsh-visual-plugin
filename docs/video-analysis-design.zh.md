# 视频解析服务设计

状态：设计已确认，尚未实现。目标版本：`0.3.0-beta.1`。

## 目标与边界

插件在不修改 DeepSeek Harness（DSH）任何源码的前提下，为现有图片视觉桥增加视频上传、标准化、关键帧解析、时间线、内部播放和追问能力。首版支持 `.mp4`、`.m4v`、`.mov`、`.avi`、`.mpg`、`.mpeg`、`.mkv`、`.webm`。音频、字幕轨、附件轨和数据轨不分析；加密、DRM 和密码保护视频直接拒绝。

插件自有上传和持久化，复用 DSH 的公开服务与 UI 插槽。视频帧发送到插件配置的视觉模型；帧描述的跨场景汇总使用 DSH 当前会话配置的文本模型。视频不进入 DSH 原生图片附件系统。

参考实现为 [YiHarvest/scene-detect-service](https://github.com/YiHarvest/scene-detect-service)。本设计复用其 PySceneDetect 思路、队列与恢复经验，但不引入常驻 FastAPI sidecar。

## 总体链路

```text
浏览器流式上传
  -> 文件大小/配额预检
  -> 文件签名 + 扩展名家族 + FFprobe 交叉验证
  -> FFmpeg 标准化并复验
  -> PySceneDetect 场景检测
  -> 普通帧 + 原始分辨率关键帧提取
  -> 删除原始上传
  -> 等待用户问题
  -> 视觉模型分批描述帧
  -> DSH 文本模型生成证据摘要
  -> 写入输入框，用户确认发送
  -> 正常 DSH 回合形成最终回答
```

持久化状态机为：

```text
uploading -> queued -> validating -> transcoding -> detecting -> extracting -> ready
ready/done -> analyzing -> summarizing -> done
analyzing -> partial -> analyzing
任意活动状态 -> failed | cancelled | paused_config
任意非删除状态 -> deleted | expired
```

`ready` 是必要的等待态：视频准备完成后，只有用户点击“解析并加入对话”才会产生模型调用。

## 模块与接口

Host 侧以一个深模块承载视频能力，`src/index.ts` 只调用类似 `installVideoFeature(ctx, options)` 的安装接口，不了解 FFmpeg 参数、清单布局、重试或配额算法。模块内部按真实变化点保留三个 seam：

- `VideoCoordinator` 是调用方和测试面对的主接口，接收上传、分析、取消、删除、查询等命令并返回不可变快照；它集中拥有状态机、会话授权、租约和恢复规则。
- `MediaEngine` 隐藏 FFmpeg、FFprobe 和 PySceneDetect。系统命令 adapter 用于生产，确定性 fake adapter 用于故障与状态机测试。
- `FrameInterpreter` 隐藏视觉 HTTP 调用和 DSH 文本汇总。生产 adapter 与 mock adapter 共享同一接口，缓存和提示注入防护留在模块内部。

`VideoRepository` 是 Coordinator 的内部 seam，生产测试优先使用临时目录中的真实文件实现，而不是把清单细节暴露给调用方。HTTP 路由、`video_describe` 工具和 React 客户端只是接口 adapter，只负责协议转换，不复制状态判断。Client 侧同样以一个安装接口注册上传按钮、dock 和右侧面板。进程参数生成器、签名解析器、清理器和迁移器均为实现细节，不从包入口导出。

## 运行时依赖与健康检查

- 支持 Linux、macOS 和 Windows。
- `ffmpeg` 与 `ffprobe` 必须位于 PATH，版本均为 `>=6.1` 且主版本一致。
- `scenedetect` 必须位于 PATH，版本范围为 `>=0.7.1 <0.8`。
- 不自动下载 FFmpeg、Python 或 PySceneDetect，也不启动常驻 Python 服务。
- 启动时执行真实能力探测：H.264 编码、`yuv420p`、PySceneDetect 解码、所需滤镜，以及可选 NVENC 单帧编码。
- HDR 输入额外要求 `zscale`/`tonemap`。缺失时只拒绝 HDR 视频并显示安装指引。
- 任一视频必需依赖不可用时，禁用视频入口但保留全部图片功能。

PySceneDetect 使用 `AdaptiveDetector` 与 `ThresholdDetector`，合并时间容差内的重复边界。CLI 若不能在单次调用中组合检测器，可执行两个受同一超时约束的检测通道；这仍是本地子进程，不是 sidecar。灵敏度对普通用户呈现“低／标准／高”，默认“标准”，实际参数写入任务记录。

## 上传与输入验证

浏览器采用单次同源流式上传，显示字节进度并支持取消；断网或刷新后重新上传，不做断点续传。服务端边接收边计数和计算 SHA-256，不把完整文件读入内存。同一会话内，相同 SHA-256 可复用产物；禁止跨会话去重。

容器家族规则：

- ISO BMFF：`.mp4`、`.m4v`、`.mov` 可互为同族别名。
- MPEG Program Stream：`.mpg`、`.mpeg` 可互为同族别名。
- AVI、Matroska、WebM 分别验证；WebM 与 Matroska 不因共享 EBML 而自动互认。
- MIME 仅作提示；空值和 `application/octet-stream` 不参与裁决。

插件检查文件头签名、FFprobe 实际格式和扩展名家族。跨家族冲突返回 `container_mismatch`，不支持格式返回 `unsupported_container`。尾部附加数据只有在完整转码成功后才允许，且不会进入标准化输出。FFmpeg 仅接收插件生成的本地路径，通过参数数组启动，禁用 stdin、网络协议和 shell 展开。

默认限制为 200 MB、10 分钟、4K；管理员可提高，但绝对上限为 2 GB、2 小时、8K 和 120 个分析帧。至少一帧可解码且时长大于零的极短视频可按单帧视频处理。多个真实视频轨时，忽略 `attached_pic`；仅有一个真实轨或唯一默认轨才接受，否则拒绝并要求用户消除歧义。

## 标准化与复验

所有视频转为 MP4、H.264、`yuv420p`，最长边 1280、最高 15 fps、CRF 26、偶数尺寸、方形像素、`+faststart`，并删除音频和元数据。禁止放大低分辨率输入。

滤镜顺序按输入能力组合：去隔行（`bwdif`）→ 应用旋转 → Alpha 合成到中性灰 → HDR/10-bit 色调映射到 SDR BT.709 → 比例缩放与偶数尺寸 → 帧率限制。无法可靠判断隔行状态时保留原扫描方式并提示。实验性 NVENC 必须通过真实单帧探测；任何实际编码失败均回退 `libx264`。

标准化后再次 FFprobe，必须确认 MP4、H.264、`yuv420p`、尺寸、帧率、主视频轨及合理的时长误差。尾部损坏、截断或只可解码部分内容时整体失败，不生成“部分视频”。

## 场景与关键帧策略

PySceneDetect 扫描标准化视频，以提高跨平台确定性。选帧规则为：

1. 保留整段视频首尾帧。
2. 每个检测场景选择中点。
3. 单场景超过 20 秒时，每 10 秒补帧。
4. 候选超额时依次保证首尾、主要场景、较高场景分数，再做时间分层填充。
5. 仅当 pHash 与像素相似度都达到严格阈值时去重；边界帧受保护，不确定时保留。

默认最多分析 48 帧，可配置为 8–120。常规帧从标准化视频提取。场景时间点确定后，从原文件额外保存最多 48 张原始分辨率关键帧；完成校验后立即删除原始上传。高清帧仅用于小字、表格等定向复查。

## 模型调用

### 视觉阶段

选择视频不会立即发送帧。用户提出问题并点击解析按钮时，界面展示视觉模型、DSH 文本模型、预计帧数以及“音频不会被分析”。视觉服务只接收帧、稳定帧编号、时间戳和当前问题，不接收会话历史、磁盘路径或其他消息。

默认每批 6 帧，最多 2 批并发；端点拒绝多图时回退单帧调用。请求 JSON 输出并严格校验：

- 批次：`frames[{frameId,timestampSeconds,description,visibleText}]`、`intervalSummary`。
- 汇总：`summary`、`timeline`、`limitations`。

插件校验帧 ID、时间范围和字段长度；解析失败时修复重试一次，再保留自由文本降级结果。视频文字、二维码和模型输出始终作为不可信数据隔离，不能成为系统指令或工具调用指令。部分批次最终失败时保留成功结果，标记 `partial`，仅重试失败批次；用户明确选择后才能使用带缺失区间说明的部分结果。

### DSH 文本汇总

点击解析时固定当前会话 `provider`、`model` 和 `reasoningEffort`；空白会话使用 `ctx.agentDefaultModel.currentSelection()`。插件通过 `ctx.llm.stream()` 发起不追加会话历史的纯文本辅助调用，不携带工具和完整会话。配置变化或恢复时路由不可用则进入 `paused_config`，不得静默换模型。

辅助调用只生成面向当前问题的证据摘要，不直接替用户作答。摘要、主要时间线、限制和 `videoId` 控制在约 4,000 字符内，经公开 `InputActions.setDraft()` 写入输入框；用户确认发送后，正常 DSH 回合生成最终回答。摘要绑定规范化问题哈希，问题发生实质变化时必须重新解析。辅助调用失败时使用确定性的本地摘要降级。

### 定向追问

注册 `video_describe(videoId, prompt, start?, end?)`。正常 DSH 模型优先使用已有时间线，信息不足时可定向复查。工具只允许所属会话访问，单次最多从标准化视频新增 12 帧，并复用已有普通帧或高清帧。视频删除或到期后返回稳定的不可用错误。

## UI 与播放

输入框左侧和右侧视频页均提供上传入口，共用同一队列。处理中可保存一条待分析问题；准备完成后提示用户确认，不自动发送。一个问题必须显式选择一个视频，输入框上方显示引用卡片；首版不做多视频对比或“最近上传”隐式推断。

右侧面板顶部显示“图片（数量）”和“视频（数量）”两张选择卡片，记忆上次选择。视频状态变化只更新徽标，不强制切换当前图片视图。视频卡包含：

- H.264 播放器、海报帧和内部直链；
- 文件名、时长、标准化大小、状态和实际场景引擎；
- 最近问题、证据摘要和折叠历史；
- 可点击并跳转播放器的时间线；
- 复制摘要、复制内部链接、重试、取消和删除。

内容路由支持 GET/HEAD、Range/206、ETag、`Content-Disposition: inline` 和 `X-Content-Type-Options: nosniff`。链接使用至少 128 位随机视频 ID，不含文件名、会话 ID 或磁盘路径，并沿用 DSH 同源认证。链接只在当前实例和保留期内有效，不是公共分享链接。

界面、错误和安装指引提供完整中文与英文并跟随 DSH 语言；模型输出跟随用户问题语言。

## 存储、配额与生命周期

默认根目录为 `$DSH_HOME/.visual_plugin/videos`，管理员可配置绝对路径。POSIX 目录/文件权限为 `0700/0600`；Windows 使用当前用户目录与 ACL。每个任务使用版本化清单、原子写入和同文件系统重命名。目录级独占锁带进程身份和心跳；其他进程无法获得锁时只禁用视频功能。升级使用幂等迁移，失败时隔离并保留旧数据。

标准化视频、视频卡、关键帧、摘要和历史从上传完成起固定保留 7 天，访问不会续期。默认最终产物配额 2 GB，管理员可调，绝对上限 100 GB。先删除过期数据，再 LRU 淘汰非活动且未引用的视频并通知用户。临时文件不计最终配额，但启动前必须满足预计峰值空间外加 1 GB，处理中剩余空间低于 512 MB 时终止并清理。单个视频最终产物仍无法装入配额时失败，不自动降质。

上传所属会话固定不变；切换会话不会转移结果。会话删除时立即取消相关进程和模型请求，并删除视频、帧、摘要与状态。用户删除视频时二次确认并立即执行同样清理。DSH 历史消息不可回写，已发送的文字摘要会保留，但链接和工具返回已删除或已过期。

## 资源、超时与失败策略

- 队列默认 1 个活动视频、最多 5 个等待任务；管理员最多把活动并发调为 2。
- 单进程默认最多 4 线程，可调但硬上限 8。
- 进程树内存默认上限 2 GB、硬上限 4 GB；持续超限时终止。
- FFprobe：15 秒。
- 转码：`max(120 秒, 视频时长 × 4)`，最多 30 分钟。
- 场景检测/抽帧：`max(60 秒, 视频时长 × 2)`，最多 15 分钟。
- 单次视觉调用：60 秒；完整任务：45 分钟。

终止时先发送温和信号，再强制结束完整进程树。确定性的格式错误不重试；中断的 FFmpeg 阶段最多重试一次；视觉瞬时错误使用指数退避。重启时恢复队列和幂等阶段，删除无主会话任务与孤立临时文件。

诊断记录仅保存阶段、错误码、工具版本、脱敏参数和最多 64 KB stderr，随视频最多保留 7 天；不保存 API Key、帧内容、完整问题或模型原始响应。插件不自动上传遥测，只提供用户主动导出的脱敏诊断包。

## 发布与验收

首个版本发布为 npm 预发行标签 `0.3.0-beta.1`，不覆盖 `latest`。所有平台运行单元测试；Linux CI 安装真实 FFmpeg/PySceneDetect，用生成式小视频验证上传、伪装格式拒绝、转码、双检测器、抽帧、恢复、删除及 Range 播放。Windows 和 macOS 运行依赖探测、路径、进程终止和纯逻辑测试，并在稳定版前完成真实安装冒烟。

稳定版 `0.3.0` 必须满足：安装说明可复现、现有图片功能零回归、迁移可恢复、异常容器与资源限制测试通过、三平台安装冒烟通过、Beta 无未解决的 P0/P1 数据安全或发布问题。
